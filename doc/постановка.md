# Постановка задачи

## 1. Название проекта
ИИ-агент для адаптации и независимой проверки PVT-модели.

## 2. Описание инженерной проблемы
Исходная композиционная модель скважины требует настройки параметров (BIC и Volume Shift) под лабораторные эксперименты (CCE, CVD, SEP). Вручную подбирать параметры долго. Кроме того, после настройки модель нужно проверить на реальных промысловых данных (ГКИ), не используя их для подбора.

## 3. Цель разработки ИИ-агента
Автоматизировать процесс подбора параметров модели с помощью внешнего Python-кода и обеспечить независимую проверку модели на реальных замерах с формированием проверяемого отчета.

## 4. Основные задачи проекта
- Разбор запроса инженера через LLM в типизированную задачу (Pydantic).
- Проверка входных данных (единицы измерения, диапазоны).
- Взаимодействие с ПО Petroleum Experts PVTP через MCP-сервер и OpenServer.
- Подбор параметров (BIC, Volume Shift) внешним кодом с логированием каждого шага.
- Сравнение результатов с эталоном и формирование отчета.

## 5. Входные данные агента
- Запрос инженера на естественном языке.
- Файлы моделей: `исходная_модель.x1sx`, `адаптированная_модель.x1sx` (как ориентир).
- Данные лабораторных экспериментов (CCE, CVD, SEP).
- Данные промысловых замеров `Свод ГКИ ЗА07.xlsx`.
- Конфигурация допусков и единиц измерения.

## 6. Ожидаемые выходные данные
- Таблица ошибок «до/после» настройки.
- Сравнение расчетных и замеренных значений (КГФ).
- Отчет с указанием источников, логов (trace_id) и статусов проверок.
- Сохраненная копия адаптированной модели.

## 7. Основные этапы работы агента
1. Получение запроса.
2. Извлечение структуры (LLM + Pydantic).
3. Проверка данных (наличие, единицы, диапазоны).
4. Передача данных в MCP-сервер.
5. Запуск расчетов в PVTP через OpenServer.
6. Цикл оптимизации (подбор параметров).
7. Фиксация результатов и формирование отчета.

## 8. Ограничения проекта
- Встроенная регрессия PVTP недоступна через API. Подбор выполняет внешний Python-код.
- Изменение модели требует обязательного подтверждения человеком.
- Данные ГКИ нельзя использовать для настройки модели (только для независимой проверки).

## 9. Используемое программное обеспечение и технологии
- Язык программирования: Python.
- LLM: Mistral / Ollama.
- Валидация: Pydantic.
- Протокол: MCP (Model Context Protocol).
- Инженерное ПО: Petroleum Experts PVTP + OpenServer API.
- Среда: Google Colab / GitHub.

## 10. Ограничения текущего этапа разработки
- Реализован программный прототип агента с тестовым адаптером (TEST_ADAPTER).
- Реальное подключение PVTP через OpenServer не выполнено.
- Численные результаты экспериментов (PSAT, CCE, CVD) не передаются.
- Поддержка SEP через MCP отсутствует.
- Изменение параметров копии модели после подтверждения не реализовано.
- Алгоритм адаптации PVT-модели и независимая проверка по ГКИ — в разработке.
- Успешный тестовый вызов MCP не является инженерным расчётом.
- Рабочие диапазоны, допуски и настройки повторных вызовов требуют согласования с преподавателем.
  ### Ограничение по PVTP (зафиксировано)

Файл модели в формате `.x1sx` отсутствует (доступен только Excel-экспорт 
`iskhodnaya_model.xlsx`). Формат `.x1sx` — проприетарный, создать его 
автоматически невозможно. Согласно разделу 3.6 ТЗ, этап интеграции с 
реальным PVTP зафиксирован как **«интеграция не проверена»**.

Агент корректно возвращает статус `SOFTWARE_UNAVAILABLE` при попытке 
реального расчёта — это ожидаемое поведение, а не ошибка.

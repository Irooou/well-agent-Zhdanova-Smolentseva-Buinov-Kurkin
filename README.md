# ИИ-агент для адаптации и проверки PVT-модели

## Краткое описание

Проект направлен на разработку ИИ-агента для автоматизации настройки композиционной PVT-модели и её независимой проверки по промысловым данным (ГКИ).

## Цель разработки

Сокращение времени ручного подбора параметров модели и минимизация ошибок за счёт использования LLM для понимания запросов инженера и программных инструментов для выполнения проверок и инженерных расчётов.

## Решаемая инженерная задача

Подбор параметров BIC и Volume Shift на основе лабораторных экспериментов PSAT, CCE, CVD и SEP с последующей независимой проверкой модели по промысловым данным без дополнительной настройки по проверочным данным.

## Реализованные функции

- Обработка запросов на естественном языке с помощью LLM.
- Приём типизированных JSON-запросов.
- Проверка структуры запросов и ответов.
- Проверка обязательных параметров, единиц измерения и диапазонов.
- Взаимодействие агента с MCP-сервером по протоколу stdio.
- Выполнение тестовых вызовов PSAT, CCE и CVD через TEST_ADAPTER.
- Обработка некорректных запросов и недоступности LLM.
- Проверка исходного текста на известные инструкции об обходе ограничений.
- Защита от повторного выполнения обработанных запросов при последовательных запусках.
- Журналирование действий агента.
- Интеграционное тестирование.

## Архитектура

Пользователь → agent.py → LLM → типизация → валидация → MCP-клиент → MCP-сервер → адаптер расчётного ПО → результат.

Типизированные запросы могут обрабатываться без обращения к LLM.

В текущей версии используется тестовый адаптер. Подключение PVTP предусмотрено архитектурой, но ещё не реализовано.

## Используемые технологии

- Python 3.12 — основной язык разработки.
- OpenAI SDK — взаимодействие с LLM через совместимый API.
- RouterAI — используемый провайдер LLM.
- Pydantic — проверка структуры ответа LLM.
- jsonschema — проверка внешних контрактов.
- FastMCP — реализация MCP-сервера.
- MCP SDK — взаимодействие клиента и сервера.
- python-dotenv — загрузка переменных окружения.
- JSONL — журналирование.

Целевое инженерное ПО: Petroleum Experts PVTP / OpenServer.

## Установка и запуск

Клонировать репозиторий:

```bash
git clone https://github.com/Irooou/well-agent-Zhdanova-Smolentseva-Buinov-Kurkin.git
cd well-agent-Zhdanova-Smolentseva-Buinov-Kurkin
```

Создать виртуальное окружение:

```bash
python3 -m venv .venv
```

Активация на macOS/Linux:

```bash
source .venv/bin/activate
```

Активация на Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установить зависимости:

```bash
python -m pip install -r requirements.txt
```

Для работы с LLM создать файл `.env` на основе `.env.example` и заполнить переменные:

```env
LLM_BASE_URL=https://routerai.ru/api/v1
LLM_API_KEY=
LLM_MODEL=deepseek/deepseek-v4-flash
```

В `LLM_API_KEY` необходимо указать собственный действующий API-ключ. Файл `.env` не должен добавляться в Git.

## Проверка работоспособности

Проверки, не требующие реального обращения к LLM:

```bash
python -m scripts.check_mcp
python -m scripts.check_agent
python -m scripts.check_security
```

Проверки с обращением к LLM:

```bash
python -m scripts.check_llm
python -m scripts.check_entrypoint
python -m scripts.check_integration
```

## Журналирование

Журналы создаются автоматически:

- `logs/llm_log.jsonl` — обработка запросов языковой моделью.
- `logs/trace_log.jsonl` — проверка входов, вызовы MCP и результаты.
- `logs/entrypoint_log.jsonl` — ошибки и отказы на уровне точки входа.

Для сопоставления записей используются `request_id`, `trace_id` и идентификатор MCP-вызова, если он получен.

## Текущий статус и ограничения

Реализован и протестирован программный прототип агента с тестовым адаптером. Успешный тестовый вызов MCP не является выполненным инженерным расчётом.

Предстоит реализовать:

- Подключение реального PVTP через OpenServer.
- Получение численных результатов экспериментов.
- Поддержку SEP через MCP.
- Изменение разрешённых параметров копии модели после подтверждения.
- Алгоритм адаптации PVT-модели.
- Независимую проверку по лабораторным и промысловым данным.
- Формирование инженерного отчёта.

Рабочие диапазоны, допуски и настройки повторных вызовов требуют согласования с преподавателем.

Проверка по ключевым фразам не обеспечивает полной защиты от prompt injection. Корректность извлечения всех параметров языковой моделью также требует дополнительного контроля.
